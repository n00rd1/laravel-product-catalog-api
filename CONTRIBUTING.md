# Руководство по внесению вклада

Спасибо за интерес к проекту Laravel Product Catalog API! Мы приветствуем вклад от сообщества.

## Как внести вклад

### 1. Форк репозитория
Создайте форк репозитория на GitHub и клонируйте его локально.

### 2. Создание ветки
```bash
git checkout -b feature/your-feature-name
# или
git checkout -b fix/your-bug-fix
```

### 3. Установка зависимостей
```bash
composer install
npm install
```

### 4. Настройка окружения
```bash
cp .env.example .env
php artisan key:generate
php artisan migrate:fresh --seed
```

### 5. Запуск тестов
```bash
# Запуск всех тестов
php artisan test

# Запуск только unit тестов
php artisan test --testsuite=Unit

# Запуск только feature тестов
php artisan test --testsuite=Feature
```

### 6. Проверка качества кода
```bash
# PHP CS Fixer
./vendor/bin/php-cs-fixer fix --dry-run --diff

# PHPStan
./vendor/bin/phpstan analyse

# PHP CodeSniffer
./vendor/bin/phpcs
```

### 7. Коммит изменений
```bash
git add .
git commit -m "feat: добавлена новая функциональность"
# или
git commit -m "fix: исправлена ошибка в API"
```

### 8. Push и Pull Request
```bash
git push origin feature/your-feature-name
```

Затем создайте Pull Request на GitHub.

## Стандарты кода

### PHP
- Следуйте PSR-12 стандарту
- Используйте строгую типизацию
- Добавляйте docblock комментарии для методов
- Покрывайте код тестами

### Git
- Используйте conventional commits
- Делайте атомарные коммиты
- Пишите понятные сообщения коммитов

### Тестирование
- Покрывайте новую функциональность тестами
- Используйте фабрики для создания тестовых данных
- Тестируйте как успешные, так и неуспешные сценарии

## Типы вкладов

### 🐛 Исправления ошибок
- Исправление багов в существующей функциональности
- Улучшение обработки ошибок
- Исправление проблем с производительностью

### ✨ Новая функциональность
- Добавление новых API endpoints
- Новые возможности фильтрации
- Улучшения в валидации

### 📚 Документация
- Улучшение README
- Добавление примеров использования
- Документирование API

### 🔧 Улучшения
- Рефакторинг кода
- Оптимизация запросов к БД
- Улучшение архитектуры

## Процесс ревью

1. **Автоматические проверки**: CI/CD pipeline запустит тесты и проверки качества кода
2. **Ревью кода**: Команда разработчиков проверит ваш код
3. **Обратная связь**: Мы предоставим конструктивную обратную связь
4. **Итерации**: При необходимости мы попросим внести изменения

## Вопросы и поддержка

Если у вас есть вопросы:

- Приложите примеры кода, если возможно
